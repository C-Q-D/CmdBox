# CmdBox 产品定义

## 文档职责

本文只记录当前已经成立的产品定义、MVP 边界和成功结果。网页版讨论的原文保存在同目录及 `docs/architecture/` 下，本文不替代原文。

## 背景与核心问题

目标用户日常积累了大量 Bash、PowerShell、CMD 等命令，但重复使用时仍要依赖记忆、笔记搜索或再次询问 AI。即使找到命令，也需要手工替换路径和参数，容易出现引号、参数顺序及 Shell 语法错误。

首个高价值场景是 Windows 超大文件夹删除：资源管理器删除大量小文件时会产生明显的扫描和 UI 开销，而更高效的命令行方式又需要用户反复查找、修改路径并承担误操作风险。

## 一句话定义

> CmdBox 是一个把常用的一次性 CLI 命令封装成可参数化操作界面，并安全、快速重复执行的桌面工具。

## 目标用户

- Developer：重复执行 Git、Docker、构建、日志和文件处理命令。
- DevOps / SRE：重复执行环境检查、部署辅助和诊断命令。
- Power User：希望用 CLI 的效率完成系统操作，但不愿反复记忆和编辑命令。

## 产品目标

1. 将“记忆命令 → 找到命令 → 修改参数 → 打开终端 → 执行”缩短为“找到任务 → 填写参数 → 预览 → 执行”。
2. 让 Command Block 同时承载命令模板、参数定义、执行环境、安全策略和结果解释，而不只是保存一段 Snippet。
3. 让用户看到的 Preview 与最终实际执行内容一致。
4. 对永久删除等破坏性操作提供结构化保护，同时不通过递归扫描牺牲核心性能。
5. CmdBox 自身的输出、日志和 UI 开销尽可能接近直接在终端执行命令的开销。

## MVP

### 核心产品闭环

```text
创建或选择 Command Block
        ↓
填写或选择参数
        ↓
生成并检查 Preview
        ↓
启动一次性进程
        ↓
实时查看 stdout / stderr
        ↓
成功、部分失败、失败或取消
        ↓
保存执行历史并可再次执行
```

### Hero Use Case

Windows 快速永久删除多个超大文件夹：

```text
选择多个文件夹
    ↓
安全检查
    ↓
Preview
    ↓
永久删除
    ↓
实时输出
    ↓
Cancel
    ↓
Success / Partial Failure / Failure
```

### 第一阶段平台与执行范围

- Windows First。
- 一次性命令，即 `Input → Run → stdout/stderr → Exit`。
- 首个 Execution Core 使用 Windows PowerShell。
- 模板阶段覆盖 PowerShell 与 CMD 的确定性序列化和执行契约。
- Bash、Zsh、macOS 和 Linux 保留为后续平台能力，不扩大首个 Windows 交付范围。

## 明确不做

MVP 不包含：

- Interactive Shell、PTY、Terminal Emulator、持续 stdin 或 REPL。
- SSH 长连接。
- 多步骤 Workflow。
- 云同步、团队协作和 Marketplace。
- Plugin、Agent 和定时任务。
- 自动 UAC 提权或默认以管理员身份运行整个应用。
- 对任意用户脚本进行语义安全证明。
- 递归扫描待删除目录来换取表面上的安全感。

## 成功结果

- 用户可在 CmdBox 中选择多个包含中文、空格或特殊字符的文件夹，看到准确 Preview 后执行删除。
- 系统会拦截磁盘根目录、系统关键目录和不明确的 Reparse Point 目标。
- Preview 后目标或 Command Block 发生变化时，Run 被拒绝并要求重新 Preview。
- 运行期间持续显示输出、耗时和状态；Cancel 终止整个进程树。
- CmdBox Core 退出后，已受管执行不会继续失控运行。
- 命令结果与日志、数据库或 UI 保存结果分离，不把记录失败误报成命令失败或成功。
- 与直接运行 PowerShell/CMD 的基准相比，CmdBox 不产生不可接受的额外开销。

## 全局产品不变量

1. 用户看到的 Preview 必须绑定完整 Execution Spec，而不是只绑定展示文本。
2. 破坏性 Built-in Command 在 Run 时必须重新读取并校验参数、路径身份和安全策略。
3. 前端不得获得任意进程执行、任意 PID 终止等通用高权限 IPC。
4. 参数必须按类型验证，并由对应 Shell Serializer 生成，不能在 React 中直接字符串替换。
5. Cancel 的单位是整个 Execution，而不是单个父进程 PID。
6. 文件夹安全检查不得递归扫描目录内容。
7. 外部命令 Outcome 由命令的 Outcome Policy 判断，不能假设只有 Exit Code 0 表示成功。
8. 日志、数据库和 UI 故障不能改变已经发生的命令结果。
