# CmdBox 产品需求

## 文档职责

本文是 CmdBox 当前产品需求的唯一权威文档，记录最终成立的产品定位、MVP 范围、用户流程、业务规则和验收条件。项目工作台只维护状态与导航，技术实现细节由架构文档负责，测试证据由《测试与验收》负责。

## 1. 产品概述

### 1.1 背景

目标用户日常会积累大量 Bash、PowerShell、CMD 等命令。重复使用时仍要依赖记忆、笔记搜索或再次询问 AI；找到命令后还需要手工替换路径和参数，容易出现引号、参数顺序和 Shell 语法错误。

首个高价值场景是 Windows 超大文件夹删除。资源管理器处理大量小文件时会产生明显的扫描和 UI 开销，高效的命令行方式却要求用户反复查找、修改路径，并自行承担不可逆误操作风险。

### 1.2 一句话定义

> CmdBox 是一个把常用的一次性 CLI 命令封装成可参数化操作界面，并安全、快速重复执行的桌面工具。

### 1.3 核心价值

传统流程：

```text
记忆或查找命令 → 复制 → 修改参数 → 打开终端 → 执行
```

CmdBox 流程：

```text
找到任务 → 填写或选择参数 → 检查 Preview → 执行
```

用户应记住“我要做什么”，而不是“这个命令怎么写”。CmdBox 不只是保存 Snippet，而是把命令模板、参数定义、Runner、安全策略和结果解释组合成一个可重复运行的任务对象。

### 1.4 目标用户

- Developer：重复执行 Git、Docker、构建、日志和文件处理命令。
- DevOps / SRE：重复执行环境检查、部署辅助和诊断命令。
- Power User：希望以 CLI 效率完成系统操作，但不愿反复记忆和编辑命令。

## 2. 产品目标与成功结果

### 2.1 产品目标

1. 把常用命令从外部笔记转成可搜索、可参数化、可直接执行的 Command Block。
2. 让用户只填写业务参数，不再手工维护数组、引号、转义和 Shell 参数顺序。
3. 确保用户看到的 Preview 与 Rust Core 实际执行的完整 `ExecutionSpec` 一致。
4. 为永久删除等破坏性操作提供结构化安全保护，但不通过递归扫描牺牲核心性能。
5. 持续显示一次性任务的 stdout、stderr、耗时和结果，并允许终止整个执行进程树。
6. 保存 Command Block 和执行历史，使同一任务可以快速重复使用。
7. 让 CmdBox 自身的观察、日志和 UI 开销尽可能接近直接在终端运行同一命令。

### 2.2 MVP 成功结果

- 用户可在 CmdBox 中选择多个包含中文、空格或特殊字符的文件夹，检查准确 Preview 后执行永久删除。
- 系统拦截卷根、系统关键目录和目标不明确的 Reparse Point。
- Preview 后参数、Command Block、Runner、工作目录、安全策略或目标身份发生变化时，Run 被拒绝并要求重新 Preview。
- 运行期间持续显示输出、耗时和状态；Cancel 终止整个受管进程树。
- CmdBox Rust Core 退出后，由其管理的一次性任务不会继续失控运行。
- 多目标删除可以明确表达全部成功、部分失败、失败、已取消以及无法确认的目标状态。
- Command Block、分类、收藏、允许记忆的参数和 Execution History 在重启后按策略恢复。
- 与直接运行 PowerShell/CMD 的基准相比，CmdBox 不产生不可接受的额外开销。

### 2.3 产品指标

- Command Block 被重复执行，而不是只创建和执行一次。
- 已有 Command Block 的“搜索到执行”流程目标小于 10 秒。
- 用户愿意持续把自己的常用命令迁移到 CmdBox。
- Hero Delete 的 CmdBox Overhead 通过真实基准确定，不能在无数据时虚构阈值。

## 3. MVP 边界

### 3.1 当前范围

- 平台：Windows First。
- 执行模式：一次性命令，即 `Input → Run → stdout/stderr → Exit`。
- Runner：首个执行核心使用系统 Windows PowerShell；MVP 同时覆盖确定性 CMD 契约，但 CMD 必须通过真实中文和特殊字符验证后才能宣称完成。
- 核心对象：Command Block、Category、Parameter State、Execution 和 Execution History。
- 参数：Text、Number、Boolean、Select、File、Folder、Files、Folders。
- 能力：创建、编辑、删除、搜索、分类、收藏、参数表单、Preview、执行、实时输出、Cancel、结果解释、历史和再次进入当前 Command Block。
- 内置场景：Windows 快速永久删除多个文件夹；高速复制和跨盘移动作为后续内置 Command Block 候选。

一次性命令不等于瞬时命令。删除数百万个小文件可能持续数分钟，任务仍需要运行时状态、耗时、实时输出和 Cancel，但任务结束后进程立即销毁，不进入交互会话。

### 3.2 明确不做

MVP 不包含：

- Interactive Shell、PTY、Terminal Emulator、持续 stdin、REPL。
- SSH 长连接和 Remote Runner。
- 多步骤 Workflow。
- Bash/Zsh 的非 Windows 正式交付。
- 云同步、团队协作和 Marketplace。
- Plugin、Agent 和定时任务。
- AI 作为每次执行的必要环节。
- Secret 存储；Token、Password、API Key 在接入系统凭据存储前不作为官方参数能力开放。
- 自动 UAC 提权或默认以管理员身份运行整个应用。
- 对任意用户脚本进行语义安全证明。
- 对待删除目录递归扫描文件数、大小、权限或内部链接来换取表面安全感。

## 4. 核心产品对象

### 4.1 Command Block

Command Block 表示一个可通过参数配置并重复执行的操作。它保存的是操作定义，不是某一次具体命令。

```text
Command Block
├─ 名称、描述、分类、标签、收藏
├─ Origin：Built-in 或 User
├─ Runner
├─ Template
├─ Parameter Definitions
├─ Working Directory
├─ 非敏感 Environment
├─ Execution Policy
├─ Safety Policy
└─ Outcome Policy
```

Built-in 由 CmdBox 提供，模板和安全策略固定且经过测试。用户编辑 Built-in 时，实际创建一份 `origin = user` 的副本，避免修改后的脚本继续沿用官方安全身份。

### 4.2 参数定义

| 类型 | 用户输入 | 主要用途 |
|---|---|---|
| Text | 普通字符串 | 分支名、容器名等 |
| Number | 有范围的数字 | 线程数、重试次数等 |
| Boolean | 开关 | 是否加入固定 Flag |
| Select | 固定选项 | 模式或预设值 |
| File / Files | 原生文件选择 | 单个或多个文件 |
| Folder / Folders | 原生目录选择 | 单个或多个目录 |

参数定义和某次执行值必须分离。默认值属于 Command Block；允许记忆的上次输入属于独立 Parameter State；Execution History 保存当次 Snapshot。

破坏性路径参数默认不记忆，避免昨天要删除的目录在下一次打开时仍被自动选中。

### 4.3 Runner

Runner 是明确的执行契约，不是任意可执行文件路径。Windows PowerShell、PowerShell 7 和 CMD 必须被区分，不能因为用户后来安装了新程序而自动改变同一个 Command Block 的执行语义。

前端只提交 Command Block ID、revision、结构化参数和 Preview 凭据；不得提交任意最终命令、任意 executable 或 PID。

### 4.4 Safety 与 Outcome

- `riskLevel` 负责产品视觉和操作文案，例如“执行”与“永久删除”。
- `SafetyPolicy` 负责结构化安全规则，例如 `DeletePaths`、`CopyPaths`、`MovePaths`。
- `OutcomePolicy` 负责解释退出码和目标级结果，不能假设只有 Exit Code 0 才是成功。
- Execution Lifecycle 与业务 Outcome 分离。取消、运行结束和业务成功/警告/失败是不同维度。

## 5. 核心用户流程

### 5.1 创建 Command Block

1. 用户点击“新建命令”。
2. 填写名称、描述、分类、Runner 和 Template。
3. 定义参数类型、默认值、是否必填、约束和是否记忆。
4. 设置工作目录、非敏感环境变量、执行、安全和结果策略。
5. Rust Core 校验 Schema、模板和策略后保存。

最简单的用户命令只要求名称、Runner 和 Template；高级配置按需展开。

### 5.2 查找并打开

用户可通过全部命令、最近使用、收藏、分类和搜索定位 Command Block。搜索范围包括名称、描述、标签和模板。列表只展示 Summary，选中后才加载完整配置和允许恢复的 Parameter State。

### 5.3 填写参数与 Preview

1. UI 根据 Parameter Definition 生成表单。
2. File/Folder 参数使用原生选择器；Files/Folders 支持多选。
3. Rust Core 校验参数、规范化路径并通过 Runner 对应的 Serializer 渲染完整执行产物。
4. Rust Core 对安全策略进行 Preview 阶段检查。
5. UI 展示可读 Preview、目标摘要、风险、警告和操作文案。
6. Preview 绑定完整 `ExecutionSpec` Hash，而不只绑定展示文本。

参数值不得在 React 中直接字符串替换，也不支持绕过转义的 Raw Parameter。

### 5.4 Run

1. 用户明确点击当前动作按钮。
2. Rust Core 重新读取 Command Block，检查 revision。
3. 重新校验参数、Runner、工作目录、环境、安全策略和目标身份。
4. 重新渲染完整执行产物并计算 Hash。
5. Hash 与用户确认的 Preview 不一致时返回稳定错误，不启动进程。
6. 匹配后创建 Execution、临时脚本和受管进程树，并立即返回 Execution ID。

破坏性命令的相同 Preview Hash 在已有运行任务时不得再次启动，以避免双击或并发请求造成重复执行。

### 5.5 运行与取消

- 运行界面显示 Started、stdout/stderr、耗时和当前状态。
- Output 只按不可信纯文本处理，不解释 HTML、控制序列或自动打开链接。
- Cancel 以 Execution ID 为单位，先显示 `CANCELLING`；只有 Rust 确认整个进程树结束后才显示 `CANCELLED`。
- Cancel 不代表回滚。对已经完成、正在处理、尚未开始或无法确认的目标应分别表达。

### 5.6 完成与历史

一次 Execution 至少记录：

- Command Block 和名称 Snapshot。
- Runner 类型、可执行文件和版本。
- Lifecycle、Outcome、Exit Code、开始时间、结束时间和耗时。
- 规范化参数、工作目录和已脱敏 Preview Snapshot。
- 目标级结果、日志路径、日志大小和截断状态。
- Persistence 与 Log Health，不得用记录失败覆盖真实命令 Outcome。

History 支持分页查看和按需读取日志。用户可以从 History 回到当前 Command Block，但旧 Snapshot 和旧 Hash 只能用于追溯，不能直接授权新的 Run；再次执行前必须按当前定义重新 Preview。

## 6. Hero Use Case：Windows 快速永久删除多个文件夹

### 6.1 用户流程

```text
打开“快速删除多个文件夹”
        ↓
选择一个或多个目录
        ↓
规范化、去重和父子折叠
        ↓
目标根对象安全检查
        ↓
显示永久删除 Preview
        ↓
Run 时重新检查并比较目标身份
        ↓
执行删除并实时显示结果
        ↓
Success / Partial Failure / Failure / Cancelled
```

### 6.2 产品界面要求

- 明确显示“永久删除，不经过回收站”。
- 主按钮使用“永久删除”，不能写成普通“执行”。
- 展示目标路径列表和目标数量，不递归统计目录大小或文件数量。
- 正常目标不使用多层烦扰确认；卷根和系统关键目录直接拦截，少数高风险用户目录根使用强化确认。
- 同时选择父目录和子目录时只执行父目录，并告知被折叠的子目录数量。
- Preview 过大时可以截断展示，但必须显示完整目标摘要，执行 Hash 仍覆盖完整内容。

### 6.3 删除安全规则

- 只接受绝对目录路径并要求目标存在。
- 拒绝卷根、UNC Share 根、Windows/System/Program Files/ProgramData、用户 Profile 根和 CmdBox App Data。
- 顶层目标是 Junction、Symbolic Link 或 Mount Point 时，Built-in 删除默认拒绝。
- Preview 和 Run 都读取 Final Path 与 Path Fingerprint；目标被删除重建或替换为链接时拒绝执行。
- Built-in PowerShell 删除使用 `-LiteralPath`，聚合每个目标的明确错误，并通过退出语义表达部分失败，不能以 `ErrorAction Continue` 后的模糊进程结果冒充全部成功。
- Built-in 删除使用安全工作目录，不能把工作目录放在待删除目标或其子树中。

## 7. 其他内置 Command Block 候选

### 7.1 高速复制文件夹

输入：Source Folder、Target Folder、Threads、Retry、Wait、No Progress。

典型执行内容：

```cmd
robocopy "D:\源文件夹" "E:\目标文件夹" /E /MT:32 /R:1 /W:1 /NP
```

Robocopy 的非零退出码需要专用 Outcome Policy；不能按普通命令规则判断。

### 7.2 高速移动文件夹

- 同盘移动：使用文件系统索引移动的确定性命令。
- 跨盘移动：使用 Robocopy 复制并清理源目录。

复制和移动不阻塞 Hero Delete 的 MVP 交付，只有完成各自 Safety/Outcome 设计和真实验证后才成为正式 Built-in。

## 8. 信息架构

桌面工作区采用三栏主结构：

```text
Sidebar
├─ 全部命令
├─ 最近使用
├─ 收藏
├─ 分类
└─ 设置

Command List
├─ 搜索、排序和新建
└─ Command Block Summary

Command Runner
├─ Command Header
├─ Parameter Form（存在 Parameter Definition 时）
├─ Command Preview
├─ Safety Decision（适用时）
├─ Execute / Cancel
├─ Execution Output（已经启动时）
└─ Execution Result（已经终止时）
```

Output 高频更新必须与表单和 Preview 的渲染边界分离。完整日志不能作为全局 UI Store 的普通大字符串保存。

### 8.1 统一 Command Workspace

所有 Command Block 共用一个 Command Workspace，不为每条命令编写独立页面。统一的是页面骨架、状态变化和操作位置；变化的是由 Command Block 定义和 Rust Core 响应决定的内容。

| 内容区域 | 数据来源 | 显示规则 |
|---|---|---|
| Command Header | Command Block 元数据 | 始终显示名称、描述、Runner 和风险级别 |
| Parameter Form | `ParameterDefinition[]` | 数组非空时按定义顺序显示；为空时整段省略，不显示无意义空状态 |
| Preview Summary | Rust Core 规范化参数摘要 | Preview 成功后显示完整数量和有界展示值，必须反映后端实际规范化结果，而不是前端原始输入的猜测 |
| Command Preview | Rust Core `previewText` | Preview 成功后显示；可截断展示，但执行 Hash 绑定完整内容 |
| Safety Decision | Rust Core Safety Decision | 不适用时省略；通过、警告或拦截使用稳定状态表达，前端不自行判断路径安全 |
| Action Bar | Rust Core `actionLabel` 与当前状态 | Ready 时执行；Running 时取消；Cancelling 时禁止重复请求；终态后提供再次配置入口 |
| Execution Output | Execution Channel | Execution 启动后显示；无输出时保留生命周期反馈，不伪造日志内容 |
| Execution Result | Lifecycle、Outcome 与健康状态 | 终态后显示；Exit Code、Outcome、Persistence、Log 和 UI Delivery 分开表达 |

Command Block 不能保存 React 组件名、HTML、任意布局、颜色或按钮位置，也不能要求前端加载命令专属代码。若新的真实命令无法由现有类型化参数、Safety Decision、Preview、Execution Output 和 Result 表达，应先增加一个可复用且可验证的共享内容能力，而不是添加命令专属页面。

### 8.2 参数到控件的稳定映射

| Parameter Definition | Command Workspace 控件 |
|---|---|
| Text | 文本输入 |
| Number | 带范围和步长的数字输入 |
| Boolean | 明确开/关含义的开关或复选控件 |
| Select | 只能选择固定 Option 的选择控件 |
| File / Folder | 单个原生文件或目录选择器 |
| Files / Folders | 多选入口、可移除值列表和数量摘要 |

参数的 `label`、`description`、必填、默认值和约束来自 Parameter Definition；参数顺序就是默认展示顺序。MVP 不增加纯展示用布局 DSL、字段分栏配置或命令自定义控件。破坏性路径参数继续遵守默认不记忆规则。

### 8.3 不同命令的内容解析

- 无参数命令：打开后省略 Parameter Form，由 Rust Core 自动生成 Preview；用户仍需看到并确认 Preview，不能直接执行。
- 单参数或多参数命令：按类型生成表单；只有当前值通过基础校验后才请求 Preview。
- 参数发生变化：立即使已有 Preview 和执行按钮失效，重新取得与新参数绑定的 Preview 后才能执行。
- 普通命令：使用普通动作和必要状态，不显示破坏性安全区域。
- 破坏性命令：显示 Rust Core 返回的 Safety Decision、警告和明确动作，例如“永久删除”。
- 无输出命令：Execution Output 显示“尚无输出”与运行状态；完成后仍展示 Outcome、Exit Code 和耗时。
- 有目标级结果的命令：终态结果使用后端返回的结构化目标列表；前端不解析 stdout 推断每个目标是否成功。

### 8.4 Command Workspace 阶段

```text
CONFIGURING → PREVIEWING → READY → STARTING → RUNNING → FINISHED
                              参数变化 ───────→ CONFIGURING
                                                └→ CANCELLING → FINISHED
```

`CONFIGURING / PREVIEWING / READY` 是 Command Workspace 的界面阶段；`STARTING / RUNNING / CANCELLING / FINISHED` 必须以 Rust Core 的 Execution Lifecycle 为准。界面阶段不得伪造或覆盖后端生命周期。

## 9. 产品状态与错误表达

### 9.1 Lifecycle

```text
PREPARING → STARTING → RUNNING → FINISHED
                         └────→ CANCELLING → FINISHED
异常恢复：INTERRUPTED
```

### 9.2 Outcome

```text
SUCCESS
WARNING
PARTIAL_FAILURE
FAILURE
NONE
```

### 9.3 独立健康状态

- Command Outcome：外部命令实际结果。
- Persistence Health：History 元数据是否成功保存。
- Log Health：完整日志是否成功写入或已截断。
- UI Delivery Health：实时输出是否完整到达当前界面。

例如命令成功而数据库写入失败时，UI 必须显示“命令执行成功；执行历史保存失败”，不能误报命令失败，也不能诱导用户重复执行不可逆操作。

## 10. 验收标准

| 编号 | 可观察行为 |
|---|---|
| AC-01 | Windows PowerShell 一次性任务可启动、流式输出、自然结束并显示 Exit Code 与耗时。 |
| AC-02 | 用户可选择多个目录，得到参数顺序、路径和转义确定的 Preview。 |
| AC-03 | Preview 后完整 Execution Spec 任一组成变化时，Run 被拒绝且不启动进程。 |
| AC-04 | 卷根、系统关键目录和不明确的顶层 Reparse Point 被安全拦截。 |
| AC-05 | Cancel 和 CmdBox Core 退出终止整个受管进程树。 |
| AC-06 | Hero Delete 正确表达全部成功、部分失败、失败、取消和无法确认的目标状态。 |
| AC-07 | Command Block、分类、参数状态和 Execution History 可按策略持久化恢复。 |
| AC-08 | 高频或长时间输出不会造成无界内存、DOM 或 IPC 增长，也不会阻塞外部进程。 |
| AC-09 | 真实 Windows 基准记录直接终端耗时、CmdBox 总耗时和 CmdBox Overhead。 |

详细验证场景和发布门禁见[测试与验收](../testing/测试与验收.md)。交付顺序和每项验收的实施归属见[CmdBox MVP 产品拆分](../开发计划/产品拆分-CmdBox-MVP.md)。
