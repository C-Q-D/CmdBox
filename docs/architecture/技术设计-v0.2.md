# CmdBox 技术设计 v0.2

## 1. 本阶段目标

本阶段冻结三件事：

```text
1. SQLite 数据结构
2. Rust ↔ TypeScript IPC Contract
3. Execution Streaming Contract
```

完成后，前端和 Rust 后端可以并行开发，不再依赖“口头约定”。

---

# 2. 一个重要调整：Execution 使用 Tauri Channel

上一版定义了：

```text
Execution Event
```

作为 Rust → React 的输出机制。

概念保留，但具体实现改为：

```text
Tauri IPC Channel
```

而不是：

```text
Global Event
```

最终结构：

```text
React
   │
   │ invoke(run_command_block)
   │ + Channel<ExecutionStreamEvent>
   ↓
Rust
   │
   ├── stdout ──┐
   ├── stderr ──┼──→ Channel
   └── finished ┘
```

Channel 只属于当前 Execution。

不需要全局监听：

```text
execution://stdout
execution://stderr
```

这样可以避免：

- 全局事件污染
- executionId 自行过滤
- Listener 生命周期复杂
- 多任务输出互相影响
- 高频输出事件性能问题

不允许出现：

```text

```

采用：

```text

        ↓
serde
        ↓
TypeScript Binding Generation
```

第一版采用：

```text
ts-rs
```

生成 TypeScript 类型。

例如 Rust：

```rust
#[serde(rename_all = "camelCase")]
struct CommandBlockSummary {
    id: String,
    name: String,
```

自动生成：

```ts

  id: string;
  name: string;
  runner: RunnerType;
  favorite: boolean;
  revision: number;

```

生成目录：

```text

```

这些文件：

> 禁止手动编辑。



# 8. ParameterDefinition 改为 Discriminated Union

上一版定义：

```ts
{
  type: ParameterType;
  defaultValue?: unknown;
  constraints?: {...}
}
```

虽然灵活，但允许产生很多非法状态。

例如：

```text

+

```

实际上没有意义。

```ts
type ParameterDefinition =
```

# 33. 数据库 Connection 模型

不让：

```text
React
↓
SQLite
```

也不让 Repository 在 Tokio async thread 上做大量同步 DB 操作。

结构：

```text
Tauri Command
      ↓
Service
      ↓
spawn_blocking
      ↓
Repository
      ↓
rusqlite
```

Database Handle：

```rust
#[derive(Clone)]
struct Database {
    connection: Arc<Mutex<Connection>>,
}
```

SQLite 调用保持同步。

Async Service 不在持有数据库锁时：

```text
await process
```

# 46. 为什么需要 Preview Hash

对于 CmdBox：

> 用户看到的命令必须和实际执行的命令完全一致。

假设：

```text
用户 Preview
↓
看到删除 D:\A
↓
Block 被修改
↓
Run
↓
实际执行另外一段 Script
```

这是不能接受的。

所以：

```text
Preview
  ↓
Normalize
  ↓
Render
  ↓
SHA-256
```

Hash 内容至少包括：

```text
commandBlockId
revision
runner
normalized parameters
rendered script
risk level
```

得到：

```text
previewHash
```

---

# 47. Run 必须携带 Preview Hash

Request：

```ts
interface RunCommandRequest {
  commandBlockId: string;

  expectedRevision: number;

  parameters: ParameterValues;

  previewHash: string;
}
```

Rust 收到以后：

```text
重新 Load Block
      ↓
检查 revision
      ↓
重新 Validate
      ↓
重新 Render
      ↓
重新计算 Hash
      ↓
与 previewHash 比较
```

不一致：

```text
STALE_PREVIEW
```

拒绝执行。

尤其适用于：

```text

```

```text
stderr task 自己直接 send
```

然后各自维护 sequence。

而是：

```text
stdout ─┐
        ├→ Output Coordinator
stderr ─┘
            ↓
        sequence++
            ↓
          Channel
```

最终：

```text
1 stdout
2 stdout
3 stderr
4 stdout
```

UI 按 sequence 展示。

---

# 56. Output 做 Chunk，不做逐字符推送

例如 Rust 从 Pipe：

```text
4KB
8KB
16KB
```

读取。

输出：

```text
ExecutionOutputEvent
```

应该按 chunk 发送，而不是：

```text
每个字符
```

或者：

```text
每次 Write-Host 都创建复杂 UI state
```

前端收到以后追加到 Buffer。

---

# 57. Encoding

React 永远只处理：

```text
UTF-8 String
```

Windows Runner 负责处理：

```text
PowerShell Encoding
CMD Code Page
External Program Output
```

因此：

```text
OS bytes
↓
Runner
↓
UTF-8 normalization
↓
Channel
↓
React
```

编码问题禁止泄漏给 UI。

---

# 58. Cancel API

```text
cancel_execution
```

Request：

```ts
interface CancelExecutionRequest {
  executionId: string;
}
```

Response：

```ts
interface CancelExecutionResponse {
  accepted: boolean;
}
```

这里：

```text
accepted = true
```

只表示：

> 已接受取消请求。

不代表进程已经退出。

真正状态：

```text
cancelled
```

仍然通过 Execution Channel / History 确认。

# 60. read_execution_log

绝不能：

```text
读取完整 800MB Log
↓
一次 IPC 返回
```

采用分页读取。

```ts
interface ReadExecutionLogRequest {
  executionId: string;

  offset: number;
```

后端对：

```text
maxBytes
```


```ts
interface ReadExecutionLogResponse {

  nextOffset: number;
```

# 61. 日志文件

```text
log_rel_path
```


# 62. ApiError

所有 IPC Error 使用统一结构。

```ts
interface ApiError {
  code: ApiErrorCode;

  message: string;

  details?: unknown;
}
```

---

# 63. ApiErrorCode

第一版固定：

```ts
type ApiErrorCode =
  | "VALIDATION_FAILED"
  | "NOT_FOUND"
  | "REVISION_CONFLICT"
  | "STALE_PREVIEW"
  | "UNSUPPORTED_RUNNER"
  | "SAFETY_BLOCKED"
  | "PROCESS_SPAWN_FAILED"
  | "EXECUTION_NOT_RUNNING"
  | "DATABASE_ERROR"
  | "INTERNAL_ERROR";
```

前端业务逻辑：

```text
只判断 code
```

而不是：

```text
if (
 error.message.includes("not found")
)
```

# 64. Validation Error

例如：

```json
{
  "code": "VALIDATION_FAILED",
  "message": "参数校验失败",
  "details": {
    "fields": [
      {
        "key": "paths",
        "message": "至少选择一个文件夹"
      }
    ]
  }
}
```

React Hook Form 可以直接将：

```text
fields
```

映射到表单错误。

# 65. Safety Block

```text

```

```json
{

```

这是：

```text
Block
```

# 66. Safety Warning

UI 显示：

```text
⚠ 即将永久删除 200 个文件夹
```

但允许继续。
