# CmdBox 技术设计

## 文档职责

本文是 CmdBox 当前总体技术设计的唯一权威文档，负责技术栈、模块边界、核心模型、数据流、数据库和 IPC 契约。不可逆路径、进程树和故障隔离的详细规则见《安全与可靠性设计》，输出链路与性能预算见《性能设计》。出现冲突时，以更具体的安全、性能约束为准，并同步修订本文。

## 1. 技术目标与边界

MVP 只实现一次性本地命令执行：

```text
Command Block
    ↓
Typed Parameters
    ↓
Validation / Normalize
    ↓
Safety Guard
    ↓
Render Execution Artifact
    ↓
Preview ExecutionSpec
    ↓
Run 时重新构建并比较
    ↓
受管本地进程
    ↓
stdout / stderr / Exit
    ↓
Outcome 与 History
```

当前不实现 Interactive Shell、PTY、持续 stdin、SSH Session、Workflow 和 Remote Runner。Windows First 的实际 Runner 是 `windowsPowerShell` 和 `cmd`；PowerShell 7、Bash、Zsh 作为未来明确 Runner 类型扩展，不能通过自动探测改变已有 Command Block 的语义。

## 2. 技术栈

| 层 | 技术与决定 |
|---|---|
| Desktop | Tauri 2 |
| Frontend | React、TypeScript、Vite |
| UI | Tailwind CSS、shadcn/ui，在出现真实界面消费者时引入 |
| State | Zustand，只保存业务与 UI 状态，不保存完整 Output |
| Form | React Hook Form + Zod，在参数表单切片引入 |
| Native Core | Rust、Tokio |
| Local DB | SQLite，通过 Rust Repository 访问 |
| DB Driver | `rusqlite` 或经实现验证后确定的 Rust SQLite 驱动 |
| IPC | Tauri Commands + per-execution Channel |
| Contract | Rust `serde` Model 为唯一数据源，使用稳定生成方案输出 TypeScript 类型 |
| Process | Rust 平台实现；Windows 使用 Win32 Process + Job Object |
| Logging | `tracing` 与独立 Execution Log |
| Package Manager | pnpm |

选择 Tauri 的核心原因是保持明确的权限边界：React 负责展示和输入，Rust Core 独占模板、进程、安全、文件系统和持久化能力。前端不直接使用 Shell Plugin 执行任意命令，也不直接连接 SQLite。

## 3. 系统拓扑与信任边界

```text
┌─────────────────────────────────────────┐
│ React / TypeScript WebView              │
│ 导航、表单、Preview、状态、日志 Viewer  │
└───────────────────┬─────────────────────┘
                    │ Typed IPC / Channel
┌───────────────────▼─────────────────────┐
│ Rust Application Services               │
│ Command / Category / Execution / History│
├─────────────────────────────────────────┤
│ Rust Core                               │
│ Model / Template / Safety / Outcome     │
├─────────────────────────────────────────┤
│ Infrastructure                          │
│ Runner / Process / SQLite / Log / FS    │
└──────────────┬──────────────────┬───────┘
               │                  │
            SQLite          Windows Process
                                   │
                          PowerShell / CMD
```

React 禁止负责：

- Shell quoting、参数序列化和模板渲染。
- Path Safety、Final Path、Fingerprint 或危险目标判断。
- 创建进程、管理 PID 或解释进程树终止。
- 直接读写数据库、任意文件或完整日志路径。
- 根据错误文案或单一 Exit Code 自行推断业务 Outcome。

Rust Core 禁止暴露以下通用 IPC：

```text
execute_shell(command)
spawn_process(executable)
kill_pid(pid)
read_any_file(path)
write_any_file(path)
```

## 4. 核心模型

### 4.1 Command Block

Command Block 使用“常用元数据列 + 嵌套 Config”模型：

```ts
interface CommandBlock {
  id: string;
  name: string;
  description?: string;
  categoryId?: string;
  tags: string[];
  favorite: boolean;
  origin: "builtin" | "user";
  runner: RunnerType;
  riskLevel: "normal" | "destructive";
  revision: number;
  config: CommandBlockConfig;
  createdAt: number;
  updatedAt: number;
  lastUsedAt?: number;
  runCount: number;
}
```

时间统一为 Unix Timestamp Milliseconds。ID、revision 和时间由 Rust 创建；更新使用 `expectedRevision` 做乐观并发控制。

```ts
interface CommandBlockConfig {
  schemaVersion: 1;
  template: string;
  parameters: ParameterDefinition[];
  workingDirectory: WorkingDirectoryConfig;
  environment: EnvironmentVariable[];
  execution: ExecutionConfig;
  safety: SafetyPolicy;
  outcome: OutcomePolicy;
}
```

### 4.2 Runner

```ts
type RunnerType =
  | "windowsPowerShell"
  | "cmd"
  | "powershell7"
  | "bash"
  | "zsh";
```

MVP 实际开放 `windowsPowerShell`；`cmd` 完成真实编码门禁后开放。Runner 由 Rust 解析到确定的系统位置，不通过可变 PATH 随意替换；History 保存 Runner Type、Executable 和 Version。

### 4.3 Parameter Definition

Parameter Definition 使用 Discriminated Union，避免 Number 同时拥有 `minItems` 等非法状态。

```ts
interface ParameterBase {
  key: string;
  label: string;
  description?: string;
  required: boolean;
  remember: boolean;
}

type ParameterDefinition =
  | TextParameter
  | NumberParameter
  | BooleanParameter
  | SelectParameter
  | FileParameter
  | FolderParameter
  | FilesParameter
  | FoldersParameter;
```

各类型约束：

- Text：`defaultValue`、`minLength`、`maxLength`、`placeholder`。
- Number：`defaultValue`、`min`、`max`、`step`。
- Boolean：明确的布尔 `defaultValue`。
- Select：固定 `options` 和可选默认值。
- File/Folder：`mustExist` 和可选默认值。
- Files/Folders：`mustExist`、`minItems`、`maxItems` 和数组默认值。

执行请求只发送 `Record<string, unknown>` 的值集合，Rust 必须根据当前 Command Block Definition 做严格类型校验。

### 4.4 Working Directory 与 Environment

```ts
type WorkingDirectoryConfig =
  | { mode: "default" }
  | { mode: "fixed"; path: string }
  | { mode: "parameter"; parameterKey: string };

interface EnvironmentVariable {
  key: string;
  value: string;
}
```

MVP 不支持 Secret，不能将 Token、Password 或 API Key 作为普通 Environment 保存。History 不保存继承到进程中的完整用户环境，只记录 Command Block 明确配置且允许记录的项。

### 4.5 Execution、Lifecycle 与 Outcome

每次运行都有独立 Execution ID。PID 只存在于 Process Manager 内部。

```text
Lifecycle:
PREPARING → STARTING → RUNNING → CANCELLING → FINISHED
                                      └────→ FINISHED
异常恢复：INTERRUPTED

Outcome:
NONE / SUCCESS / WARNING / PARTIAL_FAILURE / FAILURE
```

Lifecycle 说明执行处于哪个阶段；Outcome 说明命令契约的业务结果。Outcome 由 Command Block 的 `OutcomePolicy` 和必要的目标级结果决定，不能硬编码成 `exitCode == 0`。

### 4.6 Command Workspace 内容模型

前端使用一个深的 Command Workspace Module 承担所有 Command Block 的配置、Preview、Run、Cancel 和结果展示。它的外部 Interface 只消费三类后端事实：Command Block Definition、Preview Response 和 Execution Stream；参数控件映射、区域显隐和界面阶段属于 Module 内部实现，不扩散到每条命令。

```text
Command Block Definition ─┐
Parameter Values ─────────┼→ Command Workspace Module → 统一用户操作与可观察状态
Preview Response ─────────┤
Execution Stream ─────────┘
```

内容解析规则：

1. `config.parameters` 是参数区域的唯一 Schema；空数组表示 Parameterless Command，前端省略参数区域并自动请求 Preview。
2. Parameter Definition 的 discriminated union 映射到固定控件注册表；命令不得提供组件名、HTML、CSS、任意布局或前端代码。
3. Command Block 的 `riskLevel` 只决定风险语义；最终动作文案、安全状态、规范化摘要和警告以 Preview Response 为准。
4. Preview Hash 只要参数或 Command revision 变化就立即失效；旧 Preview 不得继续保持可执行状态。
5. Execution 启动后，Lifecycle、Output、Outcome 和健康状态由专属 Channel 驱动；前端不得从按钮点击、stdout 文本或计时器推断后端状态。
6. 某个新命令需要现有模型无法表达的内容时，先证明这是多个命令共享的稳定能力，再扩展后端 Contract 和统一 Workspace；不建立命令专属页面或旁路 IPC。

Command Workspace 的界面阶段是前端派生状态，不写入 Command Block 或 Execution History：

```ts
type CommandWorkspacePhase =
  | "configuring"
  | "previewing"
  | "ready"
  | "starting"
  | "running"
  | "cancelling"
  | "finished";
```

`configuring`、`previewing` 和 `ready` 描述用户是否拥有可执行的当前 Preview；`starting` 之后必须映射 Rust Core 的 Execution Lifecycle。通用错误作为当前阶段的结构化反馈保存，不另建会与真实 Lifecycle 竞争的假终态。

## 5. Template 与 Serializer

### 5.1 受限模板语法

MVP 只支持：

```text
{{value}}
{{#if enabled}} ... {{/if}}
{{#each paths}} ... {{this}} ... {{/each}}
```

不支持 JavaScript 表达式、Function、Eval、Arithmetic、Shell Expression、用户自定义 Helper 和 Raw Parameter。

模板先解析为 AST，缓存 Key 为 `commandBlockId + revision`。Preview 和 Run 复用同一个 Parser、Validator、Renderer 和 Serializer 实现，但 Run 必须重新读取当前数据和重新执行计算，不能直接执行 Preview 缓存产物。

### 5.2 Shell Serializer

不同 Runner 使用独立 Serializer：

```text
WindowsPowerShellSerializer
CmdSerializer
PowerShell7Serializer
BashSerializer
ZshSerializer
```

模板作者写：

```powershell
Remove-Item -LiteralPath {{path}} -Recurse -Force
```

Serializer 负责把路径生成合法 Shell Literal。Text 和 Path 都不能直接字符串替换；Number 在严格校验后输出数字；Boolean 通过条件节点生成固定模板片段；数组通过 `each` 节点逐值序列化。

### 5.3 Rendered Execution

Renderer 返回可扩展的 `RenderedExecution`，而不是把接口永久写死成一个 String：

```rust
struct RenderedExecution {
    artifact: ExecutionArtifact,
    full_size_bytes: u64,
    artifact_hash: String,
}

enum ExecutionArtifact {
    ScriptFile(ScriptArtifact),
}
```

MVP 只实现 Script File。抽象允许未来在真实性能证据支持时增加 Inline 或 Auxiliary Files，而无需重写 Execution Engine。

## 6. Preview 与 ExecutionSpec

### 6.1 Preview 流程

```text
Load Command Block
→ Validate Revision and Parameters
→ Normalize Paths and Working Directory
→ Apply Safety Policy
→ Resolve Runner
→ Render Full Artifact
→ Build CanonicalExecutionSpec
→ SHA-256
→ Return Preview
```

Preview Response 至少包含：

```ts
interface PreviewCommandResponse {
  commandBlockId: string;
  revision: number;
  runner: RunnerType;
  parameterSummaries: PreviewParameterSummary[];
  previewText: string;
  fullSizeBytes: number;
  truncated: boolean;
  riskLevel: "normal" | "destructive";
  actionLabel: string;
  safety: PreviewSafetyDecision;
  previewHash: string;
}

interface PreviewParameterSummary {
  parameterKey: string;
  label: string;
  displayValues: string[];
  totalCount: number;
  truncated: boolean;
}

interface PreviewSafetyDecision {
  state: "notApplicable" | "passed" | "warning" | "blocked";
  summary?: string;
  warnings: SafetyWarning[];
}
```

`parameterSummaries` 只提供 Rust Core 已规范化值的有界可读摘要，不是一套任意 UI Section DSL；Parameter Form 仍由 Parameter Definition 生成。数组值必须保留完整 `totalCount`，但 `displayValues` 可以截断，不能为了展示成千上万个路径制造无界 IPC 或 DOM。`previewText` 可以为 UI 性能截断，但 `previewHash` 必须覆盖完整执行内容。`safety.state = blocked` 时不得返回可执行动作状态。

### 6.2 CanonicalExecutionSpec

Hash 至少覆盖：

```text
commandBlockId
revision
runner type
runner executable and options
rendered artifact hash
normalized parameters
working directory
configured environment
safety policy version
path fingerprints
outcome policy version
```

Run Request 携带 Command Block ID、expectedRevision、结构化参数和 Preview Hash。Rust 在 Run 时重新执行 Preview 的全部读取、校验、安全和渲染步骤；新 Hash 不一致时返回 `STALE_PREVIEW`，不得创建临时脚本或进程。

## 7. Execution Engine

### 7.1 服务职责

```rust
struct ExecutionService {
    commands: CommandRepository,
    renderer: TemplateRenderer,
    safety: SafetyGuard,
    process_manager: ProcessManager,
    executions: ExecutionRepository,
    logs: ExecutionLogFactory,
}
```

完整 Run 生命周期：

```text
1. 接收结构化 Run Request
2. 重新加载并校验 Command Block revision
3. 校验参数、工作目录和环境
4. 规范化路径并执行 Safety Guard
5. 解析确定性 Runner
6. 渲染完整 Execution Artifact
7. 构建并比较 CanonicalExecutionSpec Hash
8. 对破坏性相同 Hash 执行 Single Flight Guard
9. 创建 Execution PREPARING 记录
10. 写入、Flush 并校验临时脚本完整性
11. 创建受管 Process / Job
12. 进入 RUNNING，Drain stdout/stderr
13. 接收自然退出或 Cancel
14. 根据 Outcome Policy 解释结果
15. 分别完成 Outcome、Log Health 和 Persistence Health
16. 清理临时目录和 ActiveExecution
```

### 7.2 Execution Manager

运行中任务只保存在 Rust 内存：

```rust
struct ActiveExecution {
    execution_id: String,
    started_at: i64,
    cancellation: CancellationHandle,
    process: ProcessHandle,
}
```

`ExecutionManager` 维护 `HashMap<ExecutionId, ActiveExecution>`。每个任务拥有独立进程树、Channel、Output Aggregator 和日志文件。全局锁只用于短时间 insert/get/remove，不能持锁等待进程或数据库异步工作。

### 7.3 Windows Process

Windows Runner 不能只使用简单 Spawn 后再分配 Job，因为子进程可能在分配前逃逸。目标流程是：

```text
CreateProcessW(CREATE_SUSPENDED)
→ AssignProcessToJobObject
→ ResumeThread
```

每个 Execution 使用 Job Object，并设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`；MVP 不启用 Breakaway。Cancel 终止整个 Job，Rust Core 退出导致 Job Handle 关闭并清理受管进程树。

Windows PowerShell 使用确定的系统 executable，并带：

```text
-NoLogo
-NoProfile
-NonInteractive
-ExecutionPolicy Bypass
-File <script>
```

`.ps1` 临时文件使用 UTF-8 BOM。CmdBox 不修改系统或用户 Execution Policy。CMD 的脚本编码、Code Page、输出解码和特殊字符行为必须经过真实 Windows 验证。

### 7.4 临时脚本

```text
%TEMP%\CmdBox\<execution-id>\script.ps1|cmd
```

文件名不使用用户输入。流程为创建专属目录、完整写入、Flush、Hash Verify、Spawn、进程结束后删除。History 只保存允许记录的 Preview Snapshot 和 Artifact Hash，不永久保存临时脚本。

## 8. Output Streaming

Run IPC 立即返回 Execution ID，Started、Output 和 Finished 通过当前 Execution 专属 Tauri Channel 推送，不使用全局事件。

```ts
type ExecutionStreamEvent =
  | { type: "started"; executionId: string; startedAt: number }
  | {
      type: "output";
      executionId: string;
      sequence: number;
      stream: "stdout" | "stderr";
      text: string;
    }
  | {
      type: "finished";
      executionId: string;
      lifecycle: "finished" | "interrupted";
      outcome: "success" | "warning" | "partialFailure" | "failure" | "none";
      exitCode?: number;
      finishedAt: number;
      durationMs: number;
      persistenceHealth: string;
      logHealth: string;
    };
```

stdout/stderr Reader 先尽快 Drain，再进入当前任务的 Output Coordinator。Coordinator 统一分配 sequence，并按容量或时间 Batch 后推送 Channel。UI 慢消费或断开不能阻塞 Reader；极端压力下允许实时 UI 丢弃早期数据，不能拖慢外部命令。

完整 Output 写独立日志文件，UI 使用有界 Ring Buffer 和虚拟化 Viewer。Output 不进入 Zustand，不逐 Chunk 写 SQLite，也不通过一个不断增长的大字符串维护。

## 9. IPC 契约

### 9.1 Command Block

```text
list_command_blocks
get_command_block
create_command_block
update_command_block
delete_command_block
```

列表返回 `CommandBlockSummary` 和 total，支持 query、category、favorite、sort、limit、offset。详情按 ID 加载。Update 使用 `expectedRevision`；没有匹配行时返回 `REVISION_CONFLICT`。

### 9.2 Preview 与 Execution

```text
preview_command_block
run_command_block
cancel_execution
list_active_executions
```

`cancel_execution.accepted = true` 只表示取消请求已被接受，不代表进程树已退出；最终状态以 Execution 事件和 History 为准。

### 9.3 History

```text
list_executions
get_execution
read_execution_log
```

History 必须分页。Log 按 `offset + maxBytes` 分段读取，后端对单次 `maxBytes` 设置硬上限；调用方不能提交任意文件路径。

### 9.4 统一错误

```ts
interface ApiError {
  code: ApiErrorCode;
  message: string;
  details?: unknown;
}
```

首批稳定错误码：

```text
VALIDATION_FAILED
NOT_FOUND
REVISION_CONFLICT
STALE_PREVIEW
TARGET_CHANGED
DUPLICATE_EXECUTION
UNSUPPORTED_RUNNER
SAFETY_BLOCKED
PROCESS_SPAWN_FAILED
EXECUTION_NOT_RUNNING
DATABASE_ERROR
INTERNAL_ERROR
```

前端业务逻辑只判断 `code`，不能解析 message 文本。

## 10. SQLite 与持久化

### 10.1 数据位置

```text
<AppData>/CmdBox/cmdbox.db
<AppData>/CmdBox/executions/<execution-id>.log
<Temp>/CmdBox/<execution-id>/script.*
```

数据库、持久日志和临时执行文件分离。数据库保存相对日志路径，不保存任意绝对路径供前端读取。

### 10.2 初始化

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;
```

Schema 使用正式编号 Migration，并在 Transaction 中执行：

```text
0001_initial.sql
0002_xxx.sql
```

正式升级前创建数据库备份；Migration 失败时停止进入正常工作区，不能在半初始化 Schema 上继续执行命令。

### 10.3 核心表

`categories`：ID、name、sort order 和时间；未分类使用 `NULL`，不创建伪分类。

`command_blocks`：

```text
id, name, description, category_id, tags_json,
origin, runner, risk_level, favorite, revision,
config_json, search_text, run_count, last_used_at,
created_at, updated_at
```

常用索引覆盖 category、favorite、last_used_at 和 updated_at。MVP 搜索使用规范化 `search_text LIKE ?` 并限制结果数量，不提前引入 FTS。

`command_parameter_state`：以 `(command_block_id, parameter_key)` 为主键，只保存 `remember = true` 且符合产品策略的值；Command Block 删除时级联删除。

`executions`：

```text
id, command_block_id, command_name_snapshot,
runner_type, runner_executable, runner_version,
risk_level, lifecycle, outcome, exit_code,
parameters_snapshot_json, preview_snapshot,
working_directory, target_results_json,
log_rel_path, log_size_bytes, output_truncated,
persistence_health, log_health, error_code, error_message,
started_at, finished_at, duration_ms
```

Command Block 删除后 History 保留，因此外键使用 `ON DELETE SET NULL`。应用启动时将无法证明仍在运行的遗留状态恢复为 `interrupted`，但不能伪造业务 Outcome。

`app_settings`：简单 Key-Value JSON，供 Theme、Language、History Retention 和 Output Limits 使用。

### 10.4 连接模型

同步 SQLite 操作在短 `spawn_blocking` 区域中执行。数据库 Mutex 只包围短 SQL，不得跨进程等待或其他 `await`。Execution 通常只在准备和完成阶段写少量元数据；Output 不进入数据库。

## 11. 前后端 Contract 生成

Rust `serde` Struct/Enum 是数据模型唯一 Source of Truth。稳定实现路径是由 Rust 类型生成 `src/generated/` 下的 TypeScript 类型；生成文件禁止手工编辑。Tauri command wrapper 保存在前端 `lib/ipc`，必须通过契约测试验证参数名、camelCase、枚举 tagged representation 和 Error 结构。

如果选择的类型生成库或 Tauri 版本不再兼容，应在实现切片中先做最小实验再冻结依赖，不能让两个语言手写的模型长期并行漂移。

## 12. 目录职责

目录只在出现真实消费者时创建，不使用空接口、`.gitkeep` 或未引用模块制造表面架构。

```text
src/
├─ app/                  # React 应用装配与路由/工作区
├─ components/           # 已复用的共享 UI
├─ features/
│  ├─ command-blocks/
│  ├─ command-workspace/ # 通用参数、Preview、执行与结果内容解析
│  ├─ executions/
│  ├─ categories/
│  └─ settings/
├─ generated/            # Rust 生成的 TypeScript Contract
├─ lib/                  # IPC、Buffer 等无 UI 基础能力
└─ stores/               # 低频业务/UI 状态

src-tauri/src/
├─ app/                  # AppState 与装配
├─ ipc/                  # Tauri command adapters
├─ model/                # Contract 与领域模型
├─ command/              # Command/Category services
├─ template/             # Parser、AST、Renderer、Serializer
├─ execution/            # Service、Manager、Output、Outcome
├─ process/windows/      # CreateProcessW、Job Object、Decoder
├─ safety/               # Policy、Path、Fingerprint
├─ database/             # Connection、Migration、Repository
└─ logging/              # tracing 与 Execution logs
```

## 13. 安全与性能契约

以下约束属于总体架构的一部分，详细设计不在本文重复展开：

1. WebView 不加载远程代码；CSP 和 Tauri capability 采用最小权限。
2. Preview 和 Run 两次执行 Safety Guard，并绑定完整 ExecutionSpec。
3. Destructive Built-in 使用 Final Path、Reparse Point 检查和 Path Fingerprint；安全检查不递归枚举目录内容。
4. Cancel 针对整个 Execution Job；Rust Core 退出后受管任务不能继续。
5. Output 优先级是 Drain Process > Log > UI；日志和 UI 都有硬上限。
6. 日志、数据库或 Channel 故障不能改变已经发生的命令 Outcome。
7. Output 永远按不可信文本处理。
8. Windows 文件系统、Runner 编码和进程树必须在真实 Tauri 宿主中验证。

详见[安全与可靠性设计](安全与可靠性设计.md)和[性能设计](性能设计.md)。
