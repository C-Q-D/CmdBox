# CmdBox 技术设计

## 文档职责

本文是 CmdBox 当前总体技术设计的唯一权威文档，负责技术栈、模块边界、核心模型、数据流、数据库和 IPC 契约。不可逆路径、进程树和故障隔离的详细规则见《安全与可靠性设计》，输出链路与性能预算见《性能设计》。出现冲突时，以更具体的安全、性能约束为准，并同步修订本文。

## 1. 技术目标与边界

MVP 只实现一次性本地命令执行：

```text
Command Block
    ↓
Typed Parameters
    ↓
Validation / Normalize
    ↓
Safety Guard
    ↓
Render Execution Artifact
    ↓
Preview ExecutionSpec
    ↓
Run 时重新构建并比较
    ↓
受管本地进程
    ↓
stdout / stderr / Exit
    ↓
Lifecycle 终态（当前）
    ↓
Outcome 与 History（后续单元）
```

当前不实现 Interactive Shell、PTY、持续 stdin、SSH Session、Workflow 和 Remote Runner。Windows First 的实际 Runner 是 `windowsPowerShell` 和 `cmd`；PowerShell 7、Bash、Zsh 作为未来明确 Runner 类型扩展，不能通过自动探测改变已有 Command Block 的语义。

### 当前实现基线

截至 `CMD-02`，默认正式 Registry 严格只有两个固定、无破坏的参数回显 Command Block，并已经实现六类 Typed Parameter、受限模板、可信 Preview/Run 复验、Windows PowerShell/CMD Runner、Win32 Job Object 和通用 Command Workspace。`ui-validation` feature 隔离的 5 秒 `Start-Sleep` 只用于真实宿主 Cancel 验证，不进入默认正式 Registry。当前没有 SQLite、History、Outcome Policy、持久日志或虚拟化 Output Viewer；本文后续涉及这些能力的模型均是后续单元设计，不是当前运行事实。

## 2. 技术栈

| 层 | 技术与决定 |
|---|---|
| Desktop | Tauri 2 |
| Frontend | React、TypeScript、Vite |
| UI | 当前为项目内 CSS 与 React 组件；Tailwind CSS、shadcn/ui 尚未引入 |
| State | 当前为 React 局部状态和 Ref；未来若引入 Zustand，也不得保存完整 Output |
| Form | React Hook Form 7.86.0 + Zod 4.4.3，已用于六类参数表单 |
| Native Core | 当前为 Rust 标准线程、Channel 与 Win32 API；未引入 Tokio |
| Local DB | SQLite 是后续持久化设计，当前未实现 |
| DB Driver | 后续 SQLite 单元再经实现验证确定，当前未引入 |
| IPC | 当前为 5 个 Tauri Commands；每次 Run 使用独立 Tauri Channel |
| Contract | Rust `serde` Model 为唯一数据源，使用 `ts-rs` 生成并校验 TypeScript 类型 |
| Process | Rust 平台实现；Windows 使用 Win32 Process + Job Object |
| Logging | `tracing` 与独立 Execution Log 是后续设计，当前未实现 |
| Package Manager | pnpm |

选择 Tauri 的核心原因是保持明确的权限边界：React 负责展示和输入，Rust Core 独占模板、进程、安全与受控文件系统能力；后续持久化也只能进入 Rust 边界。前端不直接使用 Shell Plugin 执行任意命令，也不直接连接 SQLite。

## 3. 系统拓扑与信任边界

```text
┌─────────────────────────────────────────┐
│ React / TypeScript WebView              │
│ 导航、表单、Preview、状态、日志 Viewer  │
└───────────────────┬─────────────────────┘
                    │ Typed IPC / Channel
┌───────────────────▼─────────────────────┐
│ Rust Application Services               │
│ Command Definition / Preview / Execution│
├─────────────────────────────────────────┤
│ Rust Core                               │
│ Model / Template / Safety / Runner      │
├─────────────────────────────────────────┤
│ Infrastructure                          │
│ Artifact / Process / Job / Output       │
└───────────────────┬─────────────────────┘
                    │
              Windows Process
                    │
           PowerShell / CMD
```

SQLite、Category、History、Outcome 和持久日志位于后续交付单元；它们不能作为解释当前 `CMD-02` 行为的前置条件。

React 禁止负责：

- Shell quoting、参数序列化和模板渲染。
- Path Safety、Final Path、Fingerprint 或危险目标判断。
- 创建进程、管理 PID 或解释进程树终止。
- 直接读写数据库、任意文件或完整日志路径。
- 根据错误文案或单一 Exit Code 自行推断业务 Outcome。

Rust Core 禁止暴露以下通用 IPC：

```text
execute_shell(command)
spawn_process(executable)
kill_pid(pid)
read_any_file(path)
write_any_file(path)
```

## 4. 核心模型

### 4.1 Command Block

当前 `CMD-02` 只在 Rust 内存 Registry 中提供两个固定 Built-in，公开 Summary/Details 不暴露模板、可执行文件、Runner options、工作目录或环境。下列“常用元数据列 + 嵌套 Config”是后续可编辑与持久化 Command Block 的目标模型：

```ts
interface CommandBlock {
  id: string;
  name: string;
  description?: string;
  categoryId?: string;
  tags: string[];
  favorite: boolean;
  origin: "builtin" | "user";
  runner: RunnerType;
  riskLevel: "normal" | "destructive";
  revision: number;
  config: CommandBlockConfig;
  createdAt: number;
  updatedAt: number;
  lastUsedAt?: number;
  runCount: number;
}
```

后续持久化模型的时间统一为 Unix Timestamp Milliseconds。ID、revision 和时间由 Rust 创建；更新使用 `expectedRevision` 做乐观并发控制。当前固定 Built-in 使用稳定字符串 ID 与 revision 1，不存在数据库更新时间字段。

```ts
interface CommandBlockConfig {
  schemaVersion: 1;
  template: string;
  parameters: ParameterDefinition[];
  workingDirectory: WorkingDirectoryConfig;
  environment: EnvironmentVariable[];
  execution: ExecutionConfig;
  safety: SafetyPolicy;
  outcome: OutcomePolicy;
}
```

### 4.2 Runner

```ts
type RunnerType =
  | "windowsPowerShell"
  | "cmd";
```

当前生成契约和真实执行均开放 `windowsPowerShell` 与 `cmd`。Runner 由 Rust 解析到确定的系统位置，不通过可变 PATH 随意替换。PowerShell 7、Bash、Zsh 以及在 History 中保存 Runner Executable/Version 都属于后续能力。

### 4.3 Parameter Definition

Parameter Definition 使用 Discriminated Union，避免 Number 同时拥有 `minItems` 等非法状态。

```ts
interface ParameterBase {
  key: string;
  label: string;
  description?: string;
  required: boolean;
  remember: boolean;
}

type ParameterDefinition =
  | TextParameter
  | NumberParameter
  | BooleanParameter
  | SelectParameter
  | FolderParameter
  | FoldersParameter;
```

各类型约束：

- Text：`defaultValue`、`minLength`、`maxLength`、`placeholder`。
- Number：`defaultValue`、`min`、`max`、`step`。
- Boolean：明确的布尔 `defaultValue`。
- Select：固定 `options` 和可选默认值。
- Folder：`mustExist` 和可选默认值。
- Folders：`mustExist`、`minItems`、`maxItems` 和数组默认值。

Preview 与 Run 请求只发送结构化 Parameter Value 集合，Rust 根据当前 Command Block Definition 做严格类型校验。File 和 Files 尚未进入当前生成契约，待出现真实 Command Block 消费者后再扩展。

### 4.4 Working Directory 与 Environment

```ts
type WorkingDirectoryConfig =
  | { mode: "default" }
  | { mode: "fixed"; path: string }
  | { mode: "parameter"; parameterKey: string };

interface EnvironmentVariable {
  key: string;
  value: string;
}
```

当前两个 Built-in 使用固定系统临时工作目录和空的显式 Environment，不提供这组配置的前端编辑能力。上述 Working Directory、Environment、Secret 与 History 规则属于后续 Command Block 持久化设计。

### 4.5 Execution、Lifecycle 与 Outcome

每次运行都有独立 UUID Execution ID。PID 只存在于 Rust Process Manager 内部，不跨越 IPC。

```text
当前可观察 Lifecycle 事件：
Started → Output* → Finished | Cancelled | Failed

后续持久化 Lifecycle：
PREPARING → STARTING → RUNNING → CANCELLING → FINISHED
异常恢复：INTERRUPTED

后续 Outcome：
NONE / SUCCESS / WARNING / PARTIAL_FAILURE / FAILURE
```

当前前端只展示 Lifecycle 与原始 Exit Code：`Finished` 表示自然结束，即使 Exit Code 非零也不推导业务失败。Outcome 由后续 Command Block `OutcomePolicy` 和必要的目标级结果解释，不能硬编码成 `exitCode == 0`。

### 4.6 Command Workspace 内容模型

前端使用一个深的 Command Workspace Module 承担所有 Command Block 的配置、Preview、Run、Cancel 和结果展示。它的外部 Interface 只消费三类后端事实：Command Block Definition、Preview Response 和 Execution Stream；参数控件映射、区域显隐和界面阶段属于 Module 内部实现，不扩散到每条命令。

```text
Command Block Definition ─┐
Parameter Values ─────────┼→ Command Workspace Module → 统一用户操作与可观察状态
Preview Response ─────────┤
Execution Stream ─────────┘
```

内容解析规则：

1. 当前 `CommandBlockDetails.parameters` 是参数区域的唯一 Schema；后续持久化模型对应 `config.parameters`。空数组表示 Parameterless Command，前端省略参数区域并按 Definition generation 自动请求 Preview 一次。
2. Parameter Definition 的 discriminated union 映射到固定控件注册表；命令不得提供组件名、HTML、CSS、任意布局或前端代码。
3. Command Block 的 `riskLevel` 只决定风险语义；最终动作文案、安全状态、规范化摘要和警告以 Preview Response 为准。
4. `executionSpecHash` 只要参数、Command revision 或完整 Execution Spec 发生变化就立即失效；旧 Preview 不得继续保持可执行状态。
5. Execution 启动后，当前 Lifecycle 与 Output 只由专属 Channel 驱动；Run response 只认证 Execution ID，不等于 Started。Outcome、Persistence Health 和 Log Health 尚未实现，前端不得从按钮点击、stdout 文本、Exit Code 或计时器自行推断。
6. 某个新命令需要现有模型无法表达的内容时，先证明这是多个命令共享的稳定能力，再扩展后端 Contract 和统一 Workspace；不建立命令专属页面或旁路 IPC。

Command Workspace 的界面阶段是前端派生状态，不写入 Command Block；当前分别维护 Preview 与 Execution 两组正交状态：

```ts
type PreviewPhase =
  | "configuring"
  | "previewing"
  | "ready";

type ExecutionPhase =
  | "ready"
  | "starting"
  | "running"
  | "cancelling"
  | "finished";
```

Preview Phase 描述用户是否拥有可执行的当前 Preview。用户点击 Run 时，前端在首个 `await` 前同步消费一次性授权并进入 `starting`；Run response 只认证 Execution ID，只有认证 `Started` 才进入 `running`，后续 Output 与唯一终态均由专属 Channel 推进。通用错误作为当前阶段的结构化反馈保存，不另建会与真实 Lifecycle 竞争的假终态。Execution History 仍属于后续持久化能力。

## 5. Template 与 Serializer

### 5.1 受限模板语法

MVP 只支持：

```text
{{value}}
{{#if enabled}} ... {{/if}}
{{#each paths}} ... {{this}} ... {{/each}}
```

不支持 JavaScript 表达式、Function、Eval、Arithmetic、Shell Expression、用户自定义 Helper 和 Raw Parameter。

模板先解析为 AST，缓存 Key 为 `commandBlockId + revision`。Preview 和 Run 复用同一个 Parser、Validator、Renderer 和 Serializer 实现，但 Run 必须重新读取当前数据和重新执行计算，不能直接执行 Preview 缓存产物。

### 5.2 Shell Serializer

当前两个 Runner 使用独立 Serializer：

```text
WindowsPowerShellSerializer
CmdSerializer
```

后续新增 Runner 时再增加对应 Serializer：

```text
PowerShell7Serializer
BashSerializer
ZshSerializer
```

模板作者写：

```powershell
Remove-Item -LiteralPath {{path}} -Recurse -Force
```

Serializer 负责把路径生成合法 Shell Literal。Text 和 Path 都不能直接字符串替换；Number 在严格校验后输出数字；Boolean 通过条件节点生成固定模板片段；数组通过 `each` 节点逐值序列化。

### 5.3 Rendered Execution

Renderer 返回可扩展的 `RenderedExecution`，而不是把接口永久写死成一个 String：

```rust
struct RenderedExecution {
    artifact: ExecutionArtifact,
    full_size_bytes: u64,
    artifact_hash: String,
}

enum ExecutionArtifact {
    ScriptFile(ScriptArtifact),
}
```

MVP 只实现 Script File。抽象允许未来在真实性能证据支持时增加 Inline 或 Auxiliary Files，而无需重写 Execution Engine。

## 6. Preview 与 ExecutionSpec

### 6.1 Preview 流程

```text
Load Command Block
→ Validate Revision and Parameters
→ Normalize Paths and Working Directory
→ Apply Safety Policy
→ Resolve Runner
→ Render Full Artifact
→ Build CanonicalExecutionSpec
→ SHA-256
→ Return Preview
```

Preview Response 至少包含：

```ts
interface PreviewCommandResponse {
  commandBlockId: string;
  revision: number;
  runner: RunnerType;
  parameterSummaries: PreviewParameterSummary[];
  previewText: string;
  fullSizeBytes: number;
  truncated: boolean;
  riskLevel: "normal" | "destructive";
  actionLabel: string;
  safety: PreviewSafetyDecision;
  executionSpecHash: string;
}

interface PreviewParameterSummary {
  parameterKey: string;
  label: string;
  displayValues: string[];
  totalCount: number;
  truncated: boolean;
}

interface PreviewSafetyDecision {
  state: "notApplicable" | "passed" | "warning" | "blocked";
  summary?: string;
  warnings: SafetyWarning[];
}
```

`parameterSummaries` 只提供 Rust Core 已规范化值的有界可读摘要，不是一套任意 UI Section DSL；Parameter Form 仍由 Parameter Definition 生成。数组值必须保留完整 `totalCount`，但 `displayValues` 可以截断，不能为了展示成千上万个路径制造无界 IPC 或 DOM。`previewText` 可以为 UI 性能截断，但 `executionSpecHash` 必须覆盖完整 Canonical Execution Spec。`safety.state = blocked` 时不得形成一次性可执行授权。

### 6.2 CanonicalExecutionSpec

当前 `CanonicalExecutionSpec` Hash 覆盖：

```text
schema version
commandBlockId
revision
runner type
runner executable and options
rendered artifact hash
normalized parameters
working directory
configured environment
runner internal environment
safety policy version
outcome policy version
```

其中 `outcome policy version` 当前只是固定的 Canonical Spec 版本标记，不表示已经实现 Outcome 解释或持久化。Destructive 单元加入目标身份校验后，`path fingerprints` 也必须进入 Canonical Spec；它不是当前两个 normal Echo Built-in 的字段。

Run Request 携带 Command Block ID、`expectedRevision`、结构化参数和 `executionSpecHash`。Rust 在 Run 时重新执行 Preview 的全部读取、校验、安全和渲染步骤；新 Hash 不一致时返回 `STALE_PREVIEW`，不得创建临时脚本或进程。前端只从不可变 `ConfirmedPreview` 深复制这份请求，并在调用前同步消费一次性授权。

## 7. Execution Engine

### 7.1 服务职责

后续整合 Repository、Outcome 和持久日志时的目标服务形状如下；当前 `CMD-02` 由 `ExecutionPlanner`、`ExecutionManager`、Runner、Artifact 与 IPC adapter 直接组成，不存在该完整结构：

```rust
struct ExecutionService {
    commands: CommandRepository,
    renderer: TemplateRenderer,
    safety: SafetyGuard,
    process_manager: ProcessManager,
    executions: ExecutionRepository,
    logs: ExecutionLogFactory,
}
```

当前 `CMD-02` Run 生命周期：

```text
1. 接收结构化 Run Request
2. 重新加载并校验 Command Block revision
3. 校验六类参数、固定工作目录和显式环境
4. 对当前 normal Built-in 形成 `notApplicable` Safety Decision
5. 解析确定性 Runner
6. 渲染完整 Execution Artifact
7. 构建并比较 CanonicalExecutionSpec Hash
8. 写入并校验唯一临时脚本 Artifact
9. 以挂起状态创建 Process，分配 Job 后恢复
10. Drain stdout/stderr，经 Aggregator/Batch 进入专属 Channel
11. 接收自然退出或按 Execution ID Cancel 整个 Job
12. 发布唯一 Finished、Cancelled 或 Failed
13. 清理临时目录和 ActiveExecution
```

Destructive Single Flight、Execution 数据库记录、Outcome Policy、持久日志及其 Health 是后续单元；不能写入当前 `CMD-02` 的运行结果。

### 7.2 Execution Manager

运行中任务只保存在 Rust 内存：

```rust
struct ActiveExecution {
    state: Arc<Mutex<ExecutionControlState>>,
    cancellation: ManagedProcessCancellation,
}
```

Execution ID 是 `HashMap` 的 key；Session supervisor 线程拥有并回收实际 Process，不把 Process Handle 存入公开或前端状态。

`ExecutionManager` 维护 `HashMap<ExecutionId, ActiveExecution>`。每个任务拥有独立进程树、事件接收器与 Output Aggregator，Tauri IPC 为每次 Run 建立专属 Channel。全局锁只用于短时间 insert/get/remove，不能持锁等待进程。独立持久日志和数据库写入尚未实现。

### 7.3 Windows Process

Windows Runner 不能只使用简单 Spawn 后再分配 Job，因为子进程可能在分配前逃逸。当前已经采用：

```text
CreateProcessW(CREATE_SUSPENDED)
→ AssignProcessToJobObject
→ ResumeThread
```

每个 Execution 使用 Job Object，并设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`；MVP 不启用 Breakaway。Cancel 终止整个 Job，Rust Core 退出导致 Job Handle 关闭并清理受管进程树。

Windows PowerShell 使用确定的系统 executable，并带：

```text
-NoLogo
-NoProfile
-NonInteractive
-ExecutionPolicy Bypass
-File <script>
```

`.ps1` 临时文件使用 UTF-8 BOM。CmdBox 不修改系统或用户 Execution Policy。CMD 使用 UTF-8 无 BOM Batch、CRLF、受控 CP65001 环境和严格增量 UTF-8 解码；PowerShell/CMD 特殊字符矩阵均由自动化覆盖，完整真实 Workspace 证据统一记录在《测试与验收》。

### 7.4 临时脚本

```text
%TEMP%\CmdBox\<execution-id>\script.ps1|cmd
```

文件名不使用用户输入。当前流程为创建专属目录、完整写入、Flush、Hash Verify、Spawn、进程结束后删除，不永久保存临时脚本。History 尚未实现；后续也只能保存允许记录的 Preview Snapshot 和 Artifact Hash。

## 8. Output Streaming

`run_command_block` 成功响应只返回并认证 Execution ID，不表示任务已经 Started。`Started`、`Output`、`Finished`、`Cancelled` 和 `Failed` 通过本次 Run 专属 Tauri Channel 推送，不使用全局事件。每个事件都携带 Execution ID 和事件级 `sequence`；前端只接受当前 run generation、匹配 ID、严格递增 sequence 且位于唯一终态之前的事件。

```ts
type ExecutionStreamEvent =
  | {
      event: "started";
      data: { executionId: string; sequence: number };
    }
  | {
      event: "output";
      data: {
        executionId: string;
        sequence: number;
        fragments: Array<{
          fragmentSequence: number;
          stream: "stdout" | "stderr";
          text: string;
        }>;
        droppedBytesBefore: number;
      };
    }
  | {
      event: "finished";
      data: {
        executionId: string;
        sequence: number;
        exitCode: number;
        durationMs: number;
        droppedOutputBytes: number;
      };
    }
  | {
      event: "cancelled";
      data: {
        executionId: string;
        sequence: number;
        durationMs: number;
        droppedOutputBytes: number;
      };
    }
  | {
      event: "failed";
      data: {
        executionId: string;
        sequence: number;
        message: string;
        durationMs: number;
        droppedOutputBytes: number;
      };
    };
```

stdout/stderr Reader 先尽快 Drain，再进入当前任务的 Output Coordinator。Coordinator 统一分配 sequence，并按容量或时间 Batch 后推送 Channel。UI 慢消费或断开不能阻塞 Reader；极端压力下允许实时 UI 丢弃早期数据，不能拖慢外部命令。

当前 React Output Buffer 最多保留 512 KiB、2048 个非空 Chunk，超过任一上限便淘汰最旧 Chunk，并累计丢弃字节。Run response 前的事件另受 2048 个事件、2048 个非空 Fragment 和 512 KiB 三重上限约束，并优先保留 Lifecycle 事件。当前 UI 直接把保留的 Chunk 渲染为 React 纯文本节点；不解析 HTML、终端控制序列，也不把 Output 链接变成可点击导航。虚拟化 Viewer、完整持久日志、SQLite Output Metadata 和约 5 MiB 的长期 Viewer 容量都属于后续性能单元。

## 9. IPC 契约

### 9.1 当前 `CMD-02` IPC

```text
list_command_blocks
get_command_block
preview_command_block
run_command_block
cancel_execution
```

当前只公开上述 5 个窄业务 Command。列表返回 Rust 固定顺序的 `CommandBlockSummary[]`，详情按稳定业务 ID 加载；模板、脚本、可执行文件、Runner options、工作目录、Environment 和 PID 均不跨越 IPC。只有 `run_command_block` 创建本次调用专属 Channel。`cancel_execution.accepted = true` 只表示取消请求已被接受，不代表进程树已经退出；最终状态只以专属 Channel 的唯一终态为准。

### 9.2 后续 IPC

```text
create_command_block
update_command_block
delete_command_block
list_active_executions
list_executions
get_execution
read_execution_log
```

这些 Command 当前均未注册。后续 History 必须分页；Log 按 `offset + maxBytes` 分段读取，后端对单次 `maxBytes` 设置硬上限，调用方不能提交任意文件路径。

### 9.3 统一错误

```ts
interface ApiError {
  code: ApiErrorCode;
  message: string;
  parameterKey?: string;
  detailCode?: string;
}
```

当前 Run 路径公开前 11 个错误码，Cancel 另公开 `CANCEL_FAILED`：

```text
COMMAND_BLOCK_NOT_FOUND
REVISION_CONFLICT
VALIDATION_FAILED
INVALID_TEMPLATE
UNSUPPORTED_RUNNER
RUNNER_UNAVAILABLE
INTERNAL_CONTRACT
STALE_PREVIEW
ARTIFACT_PREPARATION_FAILED
PROCESS_START_FAILED
EXECUTION_START_FAILED
CANCEL_FAILED
```

前端对这 12 个后端公开码使用固定安全文案；任意未知码、非对象拒绝值或字段类型错误统一收敛为本地 `IPC_FAILED`，不得回显拒绝对象内容。

前端只显示错误码对应的固定安全文案，不回显拒绝对象中的任意 message。数据库、History、Destructive Safety 等后续单元可以增加稳定错误码，但不能假装已经由当前 IPC 发布。

前端业务逻辑只判断 `code`，不能解析 message 文本。

## 10. SQLite 与持久化（后续设计）

本节是 `CMD-05`、`CMD-07` 等后续单元的目标设计。当前 `CMD-02` 没有数据库文件、Migration、Repository、Execution History 或持久日志，以下结构不能用作当前实现证据。

### 10.1 数据位置

```text
<AppData>/CmdBox/cmdbox.db
<AppData>/CmdBox/executions/<execution-id>.log
<Temp>/CmdBox/<execution-id>/script.*
```

数据库、持久日志和临时执行文件分离。数据库保存相对日志路径，不保存任意绝对路径供前端读取。

### 10.2 初始化

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;
```

Schema 使用正式编号 Migration，并在 Transaction 中执行：

```text
0001_initial.sql
0002_xxx.sql
```

正式升级前创建数据库备份；Migration 失败时停止进入正常工作区，不能在半初始化 Schema 上继续执行命令。

### 10.3 核心表

`categories`：ID、name、sort order 和时间；未分类使用 `NULL`，不创建伪分类。

`command_blocks`：

```text
id, name, description, category_id, tags_json,
origin, runner, risk_level, favorite, revision,
config_json, search_text, run_count, last_used_at,
created_at, updated_at
```

常用索引覆盖 category、favorite、last_used_at 和 updated_at。MVP 搜索使用规范化 `search_text LIKE ?` 并限制结果数量，不提前引入 FTS。

`command_parameter_state`：以 `(command_block_id, parameter_key)` 为主键，只保存 `remember = true` 且符合产品策略的值；Command Block 删除时级联删除。

`executions`：

```text
id, command_block_id, command_name_snapshot,
runner_type, runner_executable, runner_version,
risk_level, lifecycle, outcome, exit_code,
parameters_snapshot_json, preview_snapshot,
working_directory, target_results_json,
log_rel_path, log_size_bytes, output_truncated,
persistence_health, log_health, error_code, error_message,
started_at, finished_at, duration_ms
```

Command Block 删除后 History 保留，因此外键使用 `ON DELETE SET NULL`。应用启动时将无法证明仍在运行的遗留状态恢复为 `interrupted`，但不能伪造业务 Outcome。

`app_settings`：简单 Key-Value JSON，供 Theme、Language、History Retention 和 Output Limits 使用。

### 10.4 连接模型

同步 SQLite 操作在短 `spawn_blocking` 区域中执行。数据库 Mutex 只包围短 SQL，不得跨进程等待或其他 `await`。Execution 通常只在准备和完成阶段写少量元数据；Output 不进入数据库。

## 11. 前后端 Contract 生成

Rust `serde` Struct/Enum 是数据模型唯一 Source of Truth。稳定实现路径是由 Rust 类型生成 `src/generated/` 下的 TypeScript 类型；生成文件禁止手工编辑。Tauri command wrapper 保存在前端 `lib/ipc`，必须通过契约测试验证参数名、camelCase、枚举 tagged representation 和 Error 结构。

如果选择的类型生成库或 Tauri 版本不再兼容，应在实现切片中先做最小实验再冻结依赖，不能让两个语言手写的模型长期并行漂移。

## 13. 安全与性能契约

以下约束属于总体架构的一部分，详细设计不在本文重复展开：

1. WebView 不加载远程代码；CSP 和 Tauri capability 采用最小权限。
2. Preview 和 Run 两次执行 Safety Guard，并绑定完整 ExecutionSpec。
3. Destructive Built-in 使用 Final Path、Reparse Point 检查和 Path Fingerprint；安全检查不递归枚举目录内容。
4. Cancel 针对整个 Execution Job；Rust Core 退出后受管任务不能继续。
5. 当前 Output 优先级是 Drain Process > Channel > UI，Rust 队列和 UI Buffer 都有硬上限；持久日志加入后位于 Drain 与 UI 之间并必须有独立硬上限。
6. Channel 或 UI 故障不能改变已经发生的外部命令结果；后续日志、数据库和 Outcome 加入后继续保持故障隔离。
7. Output 永远按不可信文本处理。
8. Windows 文件系统、Runner 编码和进程树必须在真实 Tauri 宿主中验证。

详见[安全与可靠性设计](安全与可靠性设计.md)和[性能设计](性能设计.md)。
