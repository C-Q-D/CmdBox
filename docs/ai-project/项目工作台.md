## 决定与变更

| 日期 | 决定或变更 | 原因 | 影响 |
|---|---|---|---|
| 2026-08-22 | MVP 收缩为 Windows First 的一次性命令执行器 | 用户核心痛点是超大文件夹快速删除，不需要交互终端 | PTY、SSH 和 Workflow 移出 MVP |
| 2026-08-22 | Hero Use Case 为快速永久删除多个文件夹 | 最能验证 CmdBox 相对笔记和 Terminal 的独立价值 | 安全、性能、取消和 Outcome 成为首要约束 |
| 2026-08-22 | 同一职责只保留最终权威文档 | 用户要求去除 v0.1/v0.2 等重复版本，只维护当前最终内容 | 产品、技术、安全和性能文档按职责收敛，旧版本删除 |
| 2026-08-22 | 正式开发采用后端先行并设置前端原型门禁 | 用户要求先完成后端，任何前端开发前必须先确认界面原型 | 当前只实施 Rust 后端；后端完成不等于 `CMD-01` 产品单元完成 |
| 2026-08-23 | 所有命令使用统一 Command Workspace，内容由类型化定义和后端状态驱动 | 不同命令的参数、风险和结果不同，但不能为每条命令维护独立页面 | 先确认内容模型，再重新设计视觉原型；MVP 不引入任意 UI DSL |
| 2026-08-23 | 前端视觉采用 `editorial-field-notes` 方案 1 | 用户在三套同风格方案中明确选择第 1 张 | 以项目内视觉原型为真值；先实现无副作用前端原型，再单独规划真实 IPC |
