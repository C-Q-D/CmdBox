## 总体计划

### 目标结果

开发者可以从当前仓库直接开始 CmdBox 开发：项目具有可构建的 Tauri 2 + React + TypeScript + Rust 骨架；纯前端可用 Docker Compose Watch 一条命令进入热更新；完整桌面应用可用 Windows 主机脚本进入 Vite HMR、Tauri Watch 和 Cargo 增量编译；启动、停止、重启、依赖检查和质量检查均有可重复的低等待入口。

### 当前证据

- 工作区存在尚未归一化和验证的官方 Tauri React 初始文件，但仍带生成器临时名称，缺少锁文件、Docker 配置和开发脚本，不能视为可用项目骨架。
- Windows 主机已安装 Node `24.17.0`、pnpm `11.19.0`、Rust/Cargo `1.96.1`、MSVC Rust target、Visual Studio C++ Build Tools、WebView2、Docker Desktop `29.5.3` 和 Docker Compose `5.1.4`。
- Docker CLI 已安装，但计划创建时 Docker Desktop Engine 尚未运行。
- 本机 npm 代理 `127.0.0.1:7897` 可用；所有 pnpm 下载仅在当前进程设置代理，不修改用户级配置。
- 官方 Tauri 2 项目结构由 JavaScript 前端和 `src-tauri` Rust 项目组成；Windows 原生开发依赖 C++ Build Tools、WebView2 和 MSVC Rust toolchain。

### 用户可见完成结果

1. `scripts/web-dev.ps1` 首次构建前端容器，后续通过 Compose Watch + Vite HMR 同步源码；只有依赖清单变化时才重建镜像。
2. `scripts/dev.ps1` 在 Windows 主机按依赖指纹决定是否安装依赖，然后启动完整 Tauri Dev；前端修改使用 HMR，Rust 修改使用 Watch + Cargo Incremental。
3. `scripts/dev.ps1 -Detached`、`scripts/stop.ps1` 和 `scripts/restart.ps1` 为 AI 与高频调试提供可控的后台启动、精确停止和重启入口，不终止其他项目进程。
4. `scripts/check-env.ps1` 明确报告 Docker、Node、pnpm、Rust、MSVC、WebView2 和构建工具是否满足开发条件。
5. `pnpm check:fast` 用于日常快速反馈，`pnpm check` 用于提交前完整检查，完整 Tauri Bundle 只用于里程碑和发布。

### 重要边界

- Docker 只承载前端开发服务器和前端检查，不伪装成完整 Windows Tauri 运行环境。
- 日常修改不得反复运行完整 Tauri Bundle 或无条件安装依赖；依赖安装只在 `package.json` / `pnpm-lock.yaml` 指纹变化时发生。
- Windows Tauri Dev 是完整桌面开发主路径；Vite HMR 处理前端更新，Tauri Watch 处理 Rust 更新，Cargo 保持增量编译。
- Docker 前端路径优先使用 Compose Watch 精确同步，避免 Windows bind mount + polling 的持续高 CPU；依赖变化才触发镜像重建。
- PowerShell、CMD、Job Object、WebView2 和 Tauri 原生窗口必须在 Windows 主机验证。
- 本计划不实现 Command Block、Template Engine、Execution Manager、Safety Guard、SQLite 业务表或 Hero Delete。
- 不提前安装 Tailwind、shadcn/ui、Zustand、React Hook Form、Zod 或 SQLite 依赖；当首个真实消费者出现时再加入。
- 所有人工维护的 TypeScript、TSX、Rust 和 PowerShell/CMD 脚本遵守中文文件级、类型、字段和函数注释规则。
- 当前用户已授权完成开发环境和空项目骨架；不得借此进入 `CMD-01` 或任何产品业务实现。

### 目录职责

```text
CmdBox/
├─ src/                       # React 前端
│  ├─ app/                   # 应用装配与根界面
│  ├─ components/            # 已被界面使用的共享组件
│  ├─ features/              # 按真实产品能力逐步增加
│  ├─ lib/                   # 无 UI 的前端基础能力
│  ├─ stores/                # 出现真实跨组件状态后再加入
│  └─ types/                 # 前端契约类型
├─ src-tauri/                # Windows 原生 Tauri/Rust 项目
│  ├─ capabilities/          # Tauri 权限声明
│  └─ src/                   # Rust Core；按真实职责逐步增加模块
├─ docker/                   # 仅前端的容器开发环境
├─ scripts/                  # Windows 开发入口与环境检查
├─ docs/development/         # 唯一日常开发环境与命令说明
├─ docs/                     # 产品、架构、计划与验收
├─ compose.yaml
├─ package.json
└─ pnpm-lock.yaml
```

目录只在有真实文件时创建，不用 `.gitkeep`、空接口或未使用模块制造表面结构。
