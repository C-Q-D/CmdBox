# CmdBox 开发路线

> 来源：网页版 ChatGPT 对话“命令执行工具设计”。以下正文按当前会话读取接口返回内容原样保存，不压缩或重写。

可以。到现在为止，**产品边界、技术栈、Command Block Schema、Execution Engine、性能、安全与可靠性都已经足够明确**，继续做架构设计的边际收益已经很低了，应该进入开发阶段。

我建议开发严格按这个顺序推进：

1. **M0：Execution Core Spike**
   - 初始化 Tauri 2 + React + TypeScript + Rust
   - Windows First
   - Rust 启动 Windows PowerShell
   - 临时 `.ps1`
   - stdout / stderr 实时读取
   - Tauri Channel 批量输出
   - Execution ID
   - Cancel
   - Windows Job Object
   - CmdBox 退出自动终止进程树
   - 中文/空格/特殊字符路径测试

2. **M1：Template Engine**
   - `{{value}}`
   - `{{#if}}`
   - `{{#each}}`
   - Typed Parameter
   - PowerShell/CMD Serializer
   - `RenderedExecution`
   - Preview Hash
   - 完整单元测试

3. **M2：安全执行链**
   - Path normalize
   - Root/System Path Guard
   - Reparse Point
   - Final Path
   - Path Fingerprint
   - Preview → Run 二次校验
   - Duplicate Execution Guard
   - Outcome Policy

4. **M3：第一个真正可用功能**

   直接做你的核心场景：

   **Windows 快速删除多个超大文件夹**

   完整做到：

   ```text
   选择多个文件夹
       ↓
   安全检查
       ↓
   Preview
       ↓
   永久删除
       ↓
   实时输出
       ↓
   Cancel
       ↓
   Success / Partial Failure / Failure
   ```

5. **M4：SQLite + Command Block**
   - Migration
   - Command CRUD
   - Category
   - 参数记忆
   - Execution History
   - Log File

6. **M5：完整产品 UI**
   - Sidebar
   - Command List
   - Command Runner
   - History
   - Search
   - Favorite
   - Command Editor

这里最重要的是：**不要先花大量时间做漂亮 UI。**

第一开发目标应该是得到一个很丑、但真正可靠的程序：

```text
[选择文件夹]

D:\huge-folder

[预览]

[永久删除]

Output:
...

Exit Code: 0
Duration: 31.2s
```

然后拿它跟直接在 PowerShell/CMD 运行做 benchmark。如果这个核心链路可靠、安全、性能开销足够低，那么后面的产品开发基本都是可控的工程工作。

所以现在可以正式进入开发。**第一步就是创建项目骨架并完成 M0 Execution Core。**
