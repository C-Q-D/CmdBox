# CmdBox 测试与验收

> 当前状态：持续维护。`CMD-01` 至 `CMD-03` 已完成 React → Typed IPC → Rust Core → Windows Process 的真实 Tauri 闭环验收，并能按版本化 Policy 分离显示 Lifecycle、Outcome 与原始 Exit Code；永久删除、真实目标级结果、History、持久化和完整发布 AC 仍待后续单元实现。

## 当前证据口径与安全边界

- 本轮证据日期为 `2026-08-23` 至 `2026-08-24`，只运行两个正式参数回显 Built-in，以及 feature-only 的 5 秒短等待和受控 `exit 1/3/8/9`；这些外部验收命令没有执行删除、移动、业务文件写入、网络、注册表或其他高风险操作。Rust Core 仍按正常契约短暂创建并在终态清理自己的 Execution Artifact。
- “真实宿主”表示操作发生在 CmdBox Tauri/WebView 窗口中；“自动测试”表示 Vitest、Rust 单元或 Windows 集成测试。两类证据在下表中分别标注，不能互相冒充。
- 下表以 `<验收 worktree 根>` 和 `<项目根>` 代称本机实际选择并由 Rust 规范化的两个目录；真实 stdout 与 Preview 摘要使用相同规范化绝对路径，文档不复制不必要的本机路径。
- CMD02-S-02 的 SHA-256 是对直属项名称集合做的无副作用验收快照，用于比较运行前后内容；它不是永久删除单元未来使用的生产 `PathFingerprint`。
- Execution UUID 和 Execution Spec Hash 是本次无破坏验收的可复核身份，不是可复用授权；终态后必须重新生成 Preview。
- 本轮未取得独立 WebView console attachment，因此不声称当前 Tauri 会话的 console 为 0 error/warning/issue。可确认的是：真实流程没有可见错误提示或 Vite overlay，Vite/Tauri 会话没有编译或可见 runtime 错误，当前生产构建和自动回归通过。既有视觉原型的 Chromium console=0 仅作为历史证据保留。

## 验收层次

1. Rust 单元测试：参数验证、模板、序列化、安全判断、Outcome Policy。
2. 独立集成测试：SQLite、临时脚本、子进程、Channel 事件和日志。
3. Windows 系统集成测试：Final Path、Reparse Point、File ID、Job Object、长路径和编码。
4. 真实 Tauri 宿主验证：从 React UI 发起操作，经 Typed IPC 到 Rust Core，再观察最终文件系统和用户可见结果。
5. 性能 Benchmark：与直接在 PowerShell/CMD 中运行同一执行内容对照。

不得用底层测试代替真实宿主验证，也不得把尚未接入 UI 的底层能力描述为产品功能已经可用。

### CMD-02 验收结论

- 当前默认产品行为已经形成“双 Built-in → 六类参数 → Rust Preview → 一次性 Hash 授权 → PowerShell/CMD Run → Channel Output → 唯一终态”的真实宿主闭环。
- `ui-validation` 只用于取得真实 UI Cancel 垂直证据；默认应用和 release 的产品列表仍严格只有两个正式回显 Built-in。
- 本轮真实流程全部为无破坏命令，目录指纹与 Active Artifact 检查均未发现副作用。
- 本轮独立 WebView console attachment 未取得，不能把历史原型的 console=0 写成本轮 fresh console 结论；该限制不改变已取得的可见流程、自动回归和生产构建证据。
- 本结论不覆盖永久删除、路径 Safety Guard、PathFingerprint、History、持久化、Outcome Policy、虚拟化高频 Output Viewer 或性能 Benchmark。

### CMD-03 验收结论

- 默认产品现在会由 Rust Core 按 Command Block Definition 持有的版本化 `OutcomePolicy` 解释自然结束，并把稳定 Outcome 与原始 Exit Code 一起发布；React 只映射枚举。
- Lifecycle 与 Outcome 保持两个维度：自然完成可为 success/warning/failure，取消与 Core 内部失败为 `none`；UI 不从 stdout、message、耗时或 Exit Code 猜测。
- `ui-validation` 只用于安全宿主验收，不进入默认 Registry。全部真实命令为受控 Exit Code 或短等待，没有文件系统目标副作用。
- 类型化目标事实的纯 Rust 聚合契约已建立，但真实删除 Executor、目标级 UI 与真实 `partialFailure` 证据属于 CMD-04，不能由本结论提前宣告。
- 本轮未取得独立 WebView console attachment；该限制不改变已取得的用户可见 Tauri 流程、自动 IPC 矩阵、完整回归和生产构建证据。

## 后续 MVP 场景目录

以下场景继续作为完整 Windows MVP 的测试目录。其中已经被 CMD-01 至 CMD-03 覆盖的部分保留回归；涉及永久删除、生产 `PathFingerprint`、真实目标级结果、持久化、长期高频 Output 和 Benchmark 的部分尚未实现，不属于上述 CMD-03 完成结论。

### Execution Core 场景

- 正常执行并返回 Exit Code 0。
- 外部命令返回非零 Exit Code。
- 外部命令没有任何输出。
- stdout 和 stderr 交错输出，事件 sequence 保持可重建顺序。
- 输出包含中文、空格、单引号和非 ASCII 字符。
- PowerShell 可执行文件不存在或无法启动。
- 临时脚本创建失败、写满磁盘或完整性校验失败。
- 工作目录不存在、不是目录或权限不足。
- 运行中 Cancel。
- Cancel 与自然退出接近同时发生。
- CmdBox 前端崩溃而 Rust Core 仍存活。
- CmdBox Core 被强制退出。

### 统一 Command Workspace 场景

- Parameter Definition 为空时不显示空表单，并自动取得 Preview；执行按钮在 Preview 成功前不可用。
- Text、Number、Boolean、Select、File、Folder、Files 和 Folders 分别映射到唯一稳定控件，命令不能指定任意 React 组件。
- 参数顺序、label、description、必填、默认值和约束与当前 Command Block revision 一致。
- 参数修改后旧 `executionSpecHash` 和执行状态立即失效；新 Preview 返回前不能运行旧内容。
- Preview Summary 显示 Rust Core 规范化值；路径去重、父子折叠或规范化后不继续展示可能误导用户的原始值；大量数组值保留完整数量但有界截断展示。
- `riskLevel = normal` 且 Safety Decision 不适用时不显示破坏性区域；destructive 命令显示后端动作文案和 Safety Decision。
- Safety Decision 为 blocked 时不显示可执行主动作，并以稳定错误说明需要修改的内容。
- 命令无 stdout/stderr 时仍显示真实 Lifecycle、Outcome、Exit Code 和耗时，不伪造输出。
- 运行中参数和 Preview 只读，Cancel 进入 Cancelling；只有 Rust Core 终态事件到达后才显示 Finished/Cancelled 结果。
- 命令成功但 Persistence、Log 或 UI Delivery 异常时分别显示健康状态，不把记录失败改写成命令失败。
- 新增不同参数组合的 Command Block 时复用同一 Command Workspace，不新增命令专属页面或旁路 IPC。

### 参数、模板与 Preview 场景

- 必填参数为空。
- Number 越界或格式错误。
- Select 值不在选项集合中。
- Folder/Folders 包含中文、空格、单引号、末尾分隔符和长路径。
- 多目录中存在重复路径。
- 同时选择父目录和其子目录，Preview 只保留父目录并提示折叠结果。
- `{{value}}`、`{{#if}}` 和 `{{#each}}` 正常渲染。
- 参数值不会逃逸到新的 PowerShell/CMD 语法结构。
- Preview 展示文本被截断时，完整内容 Hash 仍稳定。
- Preview 后参数、Command revision、Runner、工作目录、环境或安全策略发生变化。
- 同一破坏性 `executionSpecHash` 被双击或并发提交时，只启动一个外部 Execution，其他请求返回稳定的重复执行错误。

### 路径与删除安全场景

- 路径不存在。
- 路径是文件而不是目录。
- `C:\`、其他卷根和 UNC Share 根目录。
- Windows、System、Program Files、ProgramData、用户 Profile 根目录和 CmdBox App Data。
- Desktop、Documents、Downloads 或 OneDrive 根目录触发 HIGH_RISK 强化确认。
- 顶层目标是 Junction、Symbolic Link 或 Mount Point。
- Preview 后目录被删除并重新创建。
- Preview 后普通目录被替换为 Junction。
- Final Path 与输入文本指向不同位置。
- 多目标中部分不存在、部分权限不足或部分文件被占用。
- 多目标删除中 A 已删除、B 处理中、C 未开始时 Cancel；结果分别表达已确认删除、失败、尚未开始或无法确认，Cancel 不暗示回滚。
- Cancel 与自然退出接近同时发生，以及删除过程中 CmdBox Core 强退；恢复后保留可证明结果并把不确定项标为无法确认。
- Safety Guard 在 Preview 和 Run 两次执行。
- 安全检查只读取目标根对象，不递归枚举目录内容。

### Outcome 与故障隔离场景

- Exit Code 0 对普通命令判定成功。
- Robocopy 等特殊工具根据 Outcome Policy 解释非零成功或警告码。
- 生命周期 `cancelled` 与命令业务 Outcome 不混为一个字段。
- 执行成功后数据库写入失败，命令结果仍保持成功，同时明确记录保存失败。
- 日志写入失败不会阻塞 Process Reader 或伪造外部命令结果。
- UI Channel 消费变慢或断开时，外部进程继续被 Rust Core 正确读取和管理。
- Output 中的 ANSI、控制字符、HTML 和 URL 只作为文本显示，不执行、不自动打开。

### 持久化场景

- 首次启动建立数据库并完成 Migration。
- Migration 失败时不继续使用半初始化 Schema。
- WAL 模式和短事务下读取 History 不长期阻塞执行完成写入。
- Output Chunk 不逐条写入 SQLite。
- 每个 Execution 使用独立日志文件，数据库只保存必要元数据。
- History 分页读取，不随历史数量增长一次性加载全部数据。
- Destructive 参数默认不记忆，除非最终产品规则明确允许。
- 从 History 进入当前 Command Block 时重新应用参数记忆策略并生成新的 Preview；历史 Snapshot/Hash 不直接授权 Run。
- History 对应的 Command Block 已删除、revision 已变化或安全策略已更新时，显示稳定提示并禁止用旧状态启动进程。
